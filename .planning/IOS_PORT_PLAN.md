# M8 — Monorepo Restructure + iOS Port Plan

## Current State

The Android app lives flat at the repo root. ~20 files are pure platform-independent
Kotlin/JVM logic (emulator, parsers, data models, FX engine, quest system). ~39 files
are Android-specific (Compose UI, AudioTrack, JNI, MIDI, DataStore). The Rust DSP
synth (`m8-synth/`) uses JNI for Android — but the core DSP is 100% portable.

## Key Decisions

### 1. Kotlin Multiplatform (KMP) for shared logic
The ~20 platform-independent files become a KMP `shared` module. Both Android and iOS
consume them. Only 3 files need `expect`/`actual` declarations:
- `Log` → `android.util.Log` / `NSLog`
- `ByteBuffer` → `java.nio.ByteBuffer` / manual byte reading
- `Math.random()` → `kotlin.random.Random` (already works cross-platform)

### 2. Rust synth gets dual FFI
Split `lib.rs` into core DSP + two FFI layers:
- `ffi_jni.rs` — current JNI exports (Android, unchanged behavior)
- `ffi_c.rs` — C-ABI `extern "C"` exports (iOS, same functions, C calling convention)
iOS loads the Rust lib as a static library via `.xcframework`. Swift calls it through
a C bridging header auto-generated by `cbindgen`.

### 3. iOS app in SwiftUI
Native SwiftUI app — not Compose Multiplatform. Reasons:
- SwiftUI is mature, performant, and what iOS devs expect
- Compose Multiplatform iOS is still experimental
- Audio (AVAudioEngine) and MIDI (CoreMIDI) must be native anyway
- You already know the M8 UI — translating Compose→SwiftUI is mechanical

### 4. Display rendering
The M8 display is a 320×240 pixel buffer. On Android it's `android.graphics.Bitmap`.
On iOS it'll be a `CGContext` / `Metal` texture. The emulator generates SLIP draw
commands — the renderer is a thin platform adapter.

## Implementation Phases

### Phase 1: Restructure monorepo (no new code)
1. Move Android app into `android/` subdirectory
2. Create `shared/` KMP module, move platform-independent files
3. Add `expect`/`actual` for Log and ByteBuffer
4. Wire `android/app` to depend on `:shared`
5. Verify Android builds and APK works identically
6. **Tag: `monorepo-restructure`**

### Phase 2: Split Rust FFI
1. Extract JNI functions from `lib.rs` into `ffi_jni.rs`
2. Create `ffi_c.rs` with C-ABI wrappers for iOS
3. Add `cbindgen.toml` for auto-generated `m8_synth.h`
4. Create `build-ios.sh` (cargo for aarch64-apple-ios targets)
5. Update `build-android.sh` (renamed from `build-rust.sh`)
6. Pre-build iOS frameworks on a Mac (you'll need to run this once)
7. **Tag: `rust-dual-ffi`**

### Phase 3: iOS app skeleton
1. Create Xcode project at `ios/M8Tracker/`
2. Add KMP shared framework dependency
3. Implement `NativeSynth.swift` calling Rust via C FFI
4. Implement `AudioEngine.swift` using AVAudioEngine + audio buffer callbacks
5. Basic SwiftUI shell: M8 display view rendering 320×240 pixel buffer
6. Touch controls: 8-button M8 pad (same layout as Android)
7. **Tag: `ios-skeleton`**

### Phase 4: iOS feature parity
1. Full SwiftUI UI: all screens (song/chain/phrase/instrument/table/mixer/fx/config)
2. Settings screen + persistence (UserDefaults or SwiftData)
3. Content browser (URLSession-based, same sources)
4. WebSocket remote M8 connection
5. CoreMIDI support
6. Keyboard/gamepad input (GCController framework)
7. Academy/tutorial system (shared logic, iOS UI)
8. **Tag: `ios-v1`**

### Phase 5: CI & unified workflow
1. GitHub Actions: Android build + iOS build in one workflow
2. Shared test suite runs on both platforms
3. Rust lib builds for all 4 targets (android arm64, android x86_64, ios arm64, ios sim)

## What changes for you after this

**Before:** Make a change in `M8Emulator.kt`, affects Android only.
**After:** `M8Emulator.kt` is in `shared/`, change affects both platforms automatically.

Any emulator logic, parser, FX engine, or data model change is write-once.
Only platform-specific UI/audio/input needs per-platform work.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| KMP iOS interop friction | Shared module is pure logic — no UI, no platform APIs. Minimal surface. |
| Rust cross-compile for iOS | Well-documented: `rustup target add aarch64-apple-ios`. Same as Android NDK flow. |
| Can't build iOS on Linux server | Phase 2 prepares everything. You run `build-ios.sh` on your MacBook once. CI uses macOS runner. |
| Compose Multiplatform temptation | Rejected. SwiftUI is the right call for a production iOS app in 2026. |
| Audio latency on iOS | AVAudioEngine with render callbacks = <10ms. Better than Android's AudioTrack. |
